How I decide an agent is ready

An agent that sounds right can still write the wrong thing into the system. So no agent of mine reaches a customer until it has passed a written set of real scenarios, and every result is checked against the record it created, not the reply text.

How it works

Each agent has a rule registry, a scenario list, and a run log of every round. When a round finds a defect, the defect becomes a new rule and a new scenario, so it can't come back quietly.

Bruce: checks passed per round

Red bars are rounds under 90%. R16 found four defects; each became a rule, and R17 passed all seven.

Three lessons the evals taught me

You can't score a tool call from the chat. Once, the agent told a technician his signed sheet was filed. It wasn't. The step that should have filed it had never run. Now every round reads the record back from the system before anything is marked as passed.

A fix from one incident must say what it doesn't cover. A rule written to stop one false claim on closed jobs ended up blocking technicians from sending photos too. The fix was to split the rule clearly into what is accepted and what is refused.

"No" and "later" are different. The agent once answered a refusal with "No problem" as if the person had only postponed. Declining and deferring now have their own replies, and both are tested.
